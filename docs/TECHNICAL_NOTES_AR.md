# ملاحظات تقنية — الاسترداد عبر إعادة استخدام stream


**المشروع البحثي بإشراف مازن بسيسو — باحث في الأمن السيبراني ومطور تقني.**
هذه الوثيقة تستخدم أمثلة عامة فقط ولا تحتوي على أي معرفات خاصة بضحية أو حادثة.

## نموذج الاسترداد

الأداة لا تفترض أن تشفير Qilin نفسه ضعيف. الهدف هو خطأ أكثر تحديداً: احتمال استخدام نفس XOR/CTR-like keystream في ملفات متعددة وبنفس المحاذاة.

إذا كان:

```text
C = P XOR K
```

فإن وجود plaintext مطابق تماماً يسمح باستخراج:

```text
K = P XOR C
```

ولا يمكن تطبيق `K` على ملف آخر إلا إذا استخدم نفس stream وبنفس offsets.

## محلل FENCP001

يقرأ التذييل الذي يبدأ بـ `FENCP001` ويعرض حقولاً بنيوية مثل version وflags وchunk size والامتداد الأصلي. البايتات غير المعروفة لا يتم الادعاء بأنها مفاتيح.

## بناء RAR4 profile

عند توفر نسختين RAR4 سليمتين أو أكثر من نفس عملية النسخ الاحتياطي، يمكن تعلم ثوابت الرأس بدون الاحتفاظ بأسماء الملفات أو hashes. الحقول غير المثبتة تظل مجهولة ولا يتم تخمينها.

## exact-pair

أمر `derive-exact` يحتاج النسخة الأصلية نفسها byte-for-byte. نسخة تاريخية مشابهة لا تكفي، خصوصاً إذا كان الملف مضغوطاً قبل تشفير ransomware.

## stable-four-way

هذا الأمر heuristic فقط لتحديد مناطق بحث محتملة، وليس إثباتاً بأن plaintext التاريخي يساوي plaintext الحديث.

## الخصوصية

التقارير تخفي المعرفات افتراضياً، وخيارات opt-in مخصصة للتقارير الخاصة فقط.
